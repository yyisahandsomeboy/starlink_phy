# 编号70恢复尝试：尚未找到通过验证的编码模型

2026-11-04，`codex_baseline`。本轮选编号70继续研究：它有91个候选资源单位，且前置66区域已有固定编码关系，起点推算比此前更有约束。**此次未恢复70的LDPC；没有把它标为已验证，也没有升级交互页面。**

首次汇报的交互界面按用户要求固定于解出66之前的 `1743f72`。后续只有用户明确要求时才修改页面。[当前汇报页面说明](FRAME1_EXPLORER.zh-CN.md)。

## 实际尝试

参数选择只用第2帧第1～8个70候选单位。其余83个单位用于随后完整校验统计；所有数据仍来自同一份已查看过的UT Austin采集，不是新采集盲测。

1. 比较136种公开AR4JA置换族与整块缩短模型、216种独立I/Q线性位标签及16种极性。最小筛选失败比例0.423828；没有得到66恢复时那样明显的编码线索。
2. 增加删余p1的投影检查，并对p1/p2擦除、不同整块缩短位置及0.02/0.04/0.08尺度做48次软译码试验，全部未收敛。
3. 检查12种分块位序列化方式，并将16384位资源单位解释为16384/8192/4096/2048位子字，形成47种设置、125832个模型/排列组合，每种检验16个极性；最小筛选失败比例0.429688，未找到候选通过。
4. 按[论文的缩短核心思路](https://arxiv.org/html/2610.29387v2#S6.SS7)，尝试将母码的输入前缀设为零，把观测中的对应区间保留为未解释位。检查20种128～8192位的前缀长度与28种母码缩短位置、216种位标签及16种极性；最小筛选失败比例0.419922，仍没有有效模型。此试验只覆盖这一有限结构，不排除其他填充或交织规则。

筛选采用固定随机种子的128/256行样本，最低值是在许多假设中选择的结果，没有校准的统计显著性含义，更不是译码成功率。筛选线只用于研究排序，没有改动冻结评价器或接收门限。数学族来源为[CCSDS 131.0-B-5](https://ccsds.org/Pubs/131x0b5.pdf)，不据此认证商业标准身份。

## MATLAB独立复核

Windows MATLAB R2024b读取9个既有协议检查点，共91个70候选单位。检查固定66矩阵，以及整块缩短、缩短加未解释位、序列化三个筛选中排名靠前的假设：所有完整硬判决校验都非零。

对第2帧第1个70单位，三个排名靠前的模型在80次软译码后仍分别剩 **1774、1245、1671** 个失败检查，不能接受。将固定66模型迁移到第2帧前8个70单位，并分别用0.02/0.04/0.08尺度，24次尝试也均未收敛。共27次软尝试涉及8个不同的单位，不是27个独立码字，也不是全部91个单位都做了软译码。

同次运行中的编号66正对照为第2帧39字，全部校验归零且重编码一致。因此保留此前66的结果，70仍需要匹配自身的H、位标签和序列化关系。清晰的16QAM点云与资源数量不足以补出这些未知量。

批处理约20秒，私有内存峰值约1.11 GiB，宿主可用内存最低约1.78 GiB；预留1 GiB、MATLAB上限2 GiB，未触发内存保护。首次研究脚本有空结构体初始化错误，修正后以同样假设复跑完成；不是把异常退出当成否定验证。

## 当前结论

这轮只排除了所测试的编码/映射/序列化假设，不能据此证明70不使用LDPC。其码长16384仍是4位×4096资源的候选解释；K、码率、完整H、生成器与业务明文均未恢复。未经新证据，不把66模型套到70，也不把失败后的硬位修改当成真实误码数。
